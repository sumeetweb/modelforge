# Design decisions

1. **Explicit manifest instead of MLflow.** Two tiny models need integrity, compatibility and reproducibility, not a tracking server and database. The registry demonstrates these contracts with less setup fragility. A team-wide registry with approvals and lineage would justify MLflow or another dedicated system.
2. **FastAPI plus TypeScript gateway.** Python owns sklearn artifacts and inference; TypeScript owns client traffic and release policy. The HTTP boundary is intentionally tested with actual processes and sockets.
3. **Iris logistic regression.** Deterministic, fast and explainable; the scaler is part of the persisted pipeline. Results demonstrate infrastructure behavior, not relevance to GoDaddy customer data.
4. **Timeouts, bounded retry, fallback, and circuit breakers.** Each addresses a different failure: a slow dependency, transient transport failure, individual pool loss, and repeated overload. Zero retries is the default; optional retries trade latency and load for transient-error tolerance. Both roles remain fallback-eligible regardless of weight.
5. **Explicit manual promotion/rollback.** Offline checks and smoke checks are implemented gates. A human inspects canary latency, fallback, and model errors. No automated rollback claim is made for model quality or routing. ECS task deployment rollback is separately configured.
6. **Private models, local loopback ports.** The only client-facing service is the gateway. Public AWS ingress is opt-in, requires TLS and restricted source CIDR, and still requires an authentication layer before broader use.
7. **Minimal cloud scope.** ECS, ECR, S3, ALB, CloudWatch and Cloud Map suffice. Kubernetes and SageMaker would add cost and operations without helping this demonstration. One NAT gateway reduces cost but creates a zonal egress dependency; one task per model means a role can be temporarily absent during failures.
8. **Locks and vulnerability gates.** `uv.lock` and `package-lock.json` preserve the tested graph, and exported Python runtime requirements include hashes. Base container tags follow Python 3.12 and Node 22 on Debian Bookworm and are not digest-pinned; pin reviewed digests before a real release. Dependency scans can fail later as new advisories appear and should prompt updates, not ignored failures.
9. **Single-operator local release files.** Atomic replacement prevents partial JSON reads, but multi-file operations are not distributed transactions. A shared release controller and compare-and-swap revision would be needed for concurrent operators.
10. **No benchmark theater.** Only executed local measurements belong in the results report. Host-mode numbers exclude containers, AWS networking, TLS, and telemetry exporters and cannot be described as production capacity.
