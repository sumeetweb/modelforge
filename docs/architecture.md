# Architecture and contracts

The gateway is the client boundary. It validates JSON before selecting a target and forwards exactly the validated body. SHA-256 of a caller's optional routing key maps into percentage buckets using a normalized unsigned 32-bit hash. Equal keys retain their assigned version for fixed configuration; changing the percentage intentionally reassigns the affected buckets. Without a key, a UUID supplies independent routing entropy. No raw key becomes a metric label or log field.

Each configured endpoint has an expected model version. The gateway checks version, schema, response count, known labels, and three finite probabilities summing to one. A response from the wrong deployment is treated as an upstream protocol failure and triggers fallback. Requests are bounded at 64 KiB/128 instances; successful upstream bodies are bounded at 128 KiB. An in-flight counter sheds load with 503 instead of maintaining an unbounded queue. This limit is per process, not per user.

The stable and candidate pools each have a process-local circuit breaker. After the configured consecutive failed requests, requests skip the open pool until cooldown; a single probe tests recovery. Failed retries count as one failed request for the breaker. Success resets the counter. Retries occur only for network, timeout, or server failures, never an invalid upstream protocol response. The other role is attempted once as a fallback sequence, using the same retry cap. Default retries are zero to avoid retry amplification during an outage. There is no cross-instance shared circuit state.

The Python service loads once during startup. Loading validates version, schema, expected feature/class contract, sklearn compatibility and checksum before trusted deserialization. HTTP handlers call a separate inference runtime through a worker thread, keeping the event loop responsive. Inference response checks reject invalid probability arrays. Shutdown drains through Uvicorn; readiness fails when no model is loaded, while liveness and metrics remain available. The HTTP caller's timeout cannot cancel CPU work already running in Python, so the request deadline is a client protection, not a compute quota.

Release configuration and executable images are separate units. Rebuilding an application image does not alter the selected model. Local volumes deliver artifacts read-only; AWS tasks fetch only their configured S3 prefix at startup. Changing versions or weights requires restarting services or deploying a new ECS task definition. Candidate promotion is explicit; fallback is automatic; rollback is an operator action. A 0% role can still serve as an emergency fallback, so traffic weight does not equal full withdrawal.

Observability has three independent paths: bounded counters and histograms to Prometheus, JSON events to stdout/CloudWatch, and optional OTLP spans through the Collector to Tempo. W3C `traceparent` connects `gateway.predict` and `model.request` to the FastAPI server span. `X-Request-ID` ties logs/responses together. Health/readiness/metric calls do not pollute model inference latency histograms. Gateway latency includes validation, upstream waits, and fallbacks; model latency covers inference and enabled fault injection.

The AWS foundation stack owns retained ECR repositories, a private versioned S3 bucket, and an optional GitHub OIDC release role. The platform stack owns a two-AZ VPC, one NAT gateway, private model/gateway Fargate services, Cloud Map DNS, an internal-by-default ALB, logs, alarms, dashboard, and gateway CPU scaling. Model security groups accept port 8000 only from the gateway security group. Model task roles have S3 access only to their selected version prefix. Execution roles use ECR/logging permissions. The release role delegates infrastructure operations to CDK bootstrap roles; review those account-wide bootstrap permissions separately before production use.
